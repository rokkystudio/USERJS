# GPT Model Picker

`GPT_MODEL_PICKER.js` — браузерный скрипт для ChatGPT, который добавляет плавающую панель выбора модели и параметров генерации и перехватывает исходящий запрос создания хода разговора.

Скрипт работает в контексте страницы ChatGPT. Он не является самостоятельным приложением и не содержит userscript-заголовок Tampermonkey/Greasemonkey.

## Файлы

- `GPT_MODEL_PICKER.js` — основной скрипт.
- `README.md` — описание запуска, интерфейса и внутренней логики.

## Возможности

Скрипт:

- загружает каталог моделей Work / TPP;
- загружает каталог обычных моделей ChatGPT;
- позволяет выбрать модель из обоих каталогов;
- поддерживает ручной `model slug`;
- позволяет выбрать `thinking_effort`;
- позволяет запросить `service_tier=priority` через переключатель «Скорость 1.5x»;
- может удерживать исходящий ход в обычном режиме Chat при выборе модели из Work-каталога;
- перехватывает `/backend-api/f/conversation`;
- показывает параметры исходящего запроса;
- читает копию потокового ответа и показывает раскрытые backend-параметры модели, thinking effort и service tier;
- защищает перехват `window.fetch` от последующей замены JavaScript-кодом страницы;
- автоматически восстанавливает перехват раз в секунду;
- сохраняет выбранные настройки и положение панели в `localStorage`.

## Запуск

Скрипт должен выполняться на странице ChatGPT после появления `document.body`.

Для ручной проверки его можно выполнить в контексте открытой страницы ChatGPT через DevTools/Snippets или другой механизм запуска пользовательского JavaScript в page context.

Повторный запуск поддерживается: перед инициализацией новый экземпляр вызывает `window.__gptModelPicker.stop()` у предыдущего экземпляра.

После запуска в правой нижней части страницы появляется панель «Модель ChatGPT».

## Интерфейс

### Модель

Список содержит:

- `Auto — не менять slug`;
- модели Work / TPP;
- обычные модели ChatGPT;
- ручной slug, если сохранённое значение отсутствует в загруженных каталогах.

Выбор применяется сразу и сохраняется в `localStorage`.

### Ручной slug

Поле позволяет указать идентификатор модели напрямую. Значение применяется при вводе и сохраняется как текущая модель.

### Как сильно думать

Доступные значения:

- `auto`;
- `min`;
- `standard`;
- `extended`;
- `xhigh`;
- `max`;
- `ultra`.

`auto` сохраняет штатный `thinking_effort` исходящего запроса.

Если каталог выбранной модели содержит список поддерживаемых thinking effort, неподдерживаемые значения отключаются в списке. Уже выбранное значение остаётся видимым, чтобы несовместимость не маскировалась.

### Скорость 1.5x

При включении скрипт задаёт:

`service_tier = "priority"`

Если исходный payload содержит `backend_service_tier`, он также получает значение `priority`.

При выключенном переключателе штатный service tier не удаляется и не подменяется.

### Оставаться в Chat

Переключатель включён по умолчанию.

Для вручную выбранной модели и обычного `primary_assistant` скрипт:

- задаёт `conversation_mode = { kind: "primary_assistant" }`;
- удаляет `conversation_origin` из исходящего payload;
- задаёт `chat_mode = "chat"`, если поле уже присутствует;
- удаляет `tpp_work_handoff_conversion`, если поле присутствует;
- сохраняет выбранный model slug в модельных полях payload.

Gizmo/custom-GPT режимы не преобразуются в `primary_assistant`.

Режим не выполняет серверный rollback уже преобразованного Work-разговора. Он управляет параметрами перехваченного исходящего хода.

## Кнопки

### Применить сейчас

Повторно применяет значение поля ручного slug, перерисовывает список моделей и восстанавливает защитный перехват `window.fetch`.

Кнопка является ручным резервом: обычный выбор модели применяется без неё.

### Обновить каталоги

Восстанавливает перехват и повторно загружает каталоги Work / TPP и ChatGPT.

При ошибке загрузки предусмотрено до двух автоматических повторов с задержкой 1500 мс.

### Вернуть перехват

Проверяет descriptor `window.fetch` и возвращает защитный accessor, если страница или другой JavaScript заменили его.

## Диагностика панели

Панель показывает пять состояний:

- состояние перехвата `fetch`;
- состояние каталогов моделей;
- выбранные модель, thinking effort, скорость и режим;
- параметры последнего исходящего запроса;
- параметры, обнаруженные в ответе backend.

Если backend возвращает другой `resolved_model_slug`, чем был запрошен, строка Backend отображает переход от запрошенной модели к фактически раскрытой.

## Перехват fetch

Скрипт сохраняет исходный `window.fetch` как `baseFetch`, а текущую штатную обёртку страницы — как `downstreamFetch`.

На `window.fetch` устанавливается accessor:

- getter всегда возвращает перехватчик скрипта;
- setter принимает новую штатную обёртку как нижний слой.

Защита от рекурсивного входа действует только во время синхронного вызова нижнего `fetch`. Ожидание сетевого Promise не блокирует перехват параллельных запросов.

Запросы, не относящиеся к `/backend-api/f/conversation`, передаются нижнему слою без изменения payload.

## Изменение conversation payload

Для выбранной вручную модели скрипт задаёт `payload.model`.

Если в payload уже присутствуют соответствующие поля, синхронизируются:

- `model_slug`;
- `requested_model_slug`;
- `backend_model`.

Для выбранного thinking effort задаётся `thinking_effort`, а существующий `backend_thinking_effort` синхронизируется с ним.

В режиме Auto модельный slug не подменяется.

## Каталоги моделей

Используются backend-методы страницы:

- `/backend-api/tpp/models/?supports_model_picker_upgrade_presets=true`;
- `/backend-api/models?iim=false&is_gizmo=false&supports_model_picker_upgrade_presets=true`.

Если первый запрос Work-каталога отвечает HTTP 404, скрипт получает текущую сессию через `/api/auth/session` и повторяет запрос с bearer-токеном.

Access token используется только в памяти для запроса каталога. Скрипт не записывает его в DOM, console или `localStorage`.

## localStorage

Скрипт использует следующие ключи:

- `gpt-model-picker.selected-model.v2`;
- `gpt-model-picker.thinking-effort.v1`;
- `gpt-model-picker.fast-mode.v1`;
- `gpt-model-picker.force-chat.v1`;
- `gpt-model-picker.position.v1`;
- `gpt-model-picker.collapsed.v1`.

## Управление из консоли

Текущий экземпляр доступен как:

`window.__gptModelPicker`

Экспортируются:

- `config`;
- `state`;
- `start()`;
- `stop()`;
- `loadModels()`;
- `setSelectedModel(modelSlug, persist)`;
- `setSelectedThinkingEffort(thinkingEffort, persist)`;
- `setFastModeEnabled(enabled, persist)`;
- `setForceChatEnabled(enabled, persist)`;
- `restoreHook()`.

`stop()` останавливает таймер контроля, возвращает нижний `fetch`, удаляет панель и добавленные стили.

## Ограничения

Скрипт зависит от внутренних backend-методов, структуры payload и frontend-поведения ChatGPT. Эти интерфейсы не являются стабильным публичным API и могут меняться.

Перехват `/backend-api/f/conversation` выполняется только после того, как frontend сформировал запрос. Если интерфейс ChatGPT блокирует отправку до создания этого запроса, данный перехват не получает управление.

Уже выполненный серверный Work handoff не отменяется изменением следующего conversation payload. Для такого состояния требуется отдельная работа с механизмом возврата Work-разговора.
