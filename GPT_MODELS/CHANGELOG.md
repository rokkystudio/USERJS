# CHANGELOG

История версий GPT Model Picker.

Новые версии добавляются отдельными файлами `GPT_MODEL_PICKER_vX.Y.Z.js`. Файлы предыдущих версий сохраняются без редактирования.

## 1.0.12 — 2026-09-25

Добавлено открытие чатов в новой вкладке из меню боковой панели.

- Правый клик по строке разговора открывает её штатное меню ChatGPT через кнопку «Действия чата».
- Наблюдатель DOM обрабатывает создание видимого меню чата и добавляет «Открыть в новой вкладке» самым первым пунктом.
- Связь меню и строки чата определяется по aria-labelledby, aria-controls и aria-owns компонентов Radix.
- Меню «Новый чат» использует DOM-шаблон настоящего меню ChatGPT и содержит единственный пункт «Открыть в новой вкладке».
- Обычные чаты используют ключ разговора из DOM; проектные — ID из props React-строки.

Локальная проверка:

`node --check GPT_MODEL_PICKER_v1.0.12.js`

## 1.0.11 — 2026-09-24

Исправлен вид переключателей формы в окружениях с глобальным `appearance: none`.

- Для checkbox принудительно включён нативный вид с сохранением пользовательского accent-color.
- Все элементы формы получили уникальные `id` и `name`; подписи явно связаны с соответствующими полями.
- Вмешательство стилей ограничено checkbox внутри панели.

Список выбора модели содержит статические разделы поверх загружаемых каталогов Work и обычного ChatGPT.

- `Исторические модели` содержит прежние ChatGPT slug и `research` для Deep Research.
- `Экспериментальные модели OpenAI API` содержит имена моделей со страницы OpenAI API `All models`: flagship, image, realtime/audio, Daybreak, life sciences, open-weight, embeddings и more/deprecated models.
- Пункты статических разделов отображают badge `[история]` или `[API-only]` после slug.
- Выбранная модель ищется среди загруженных каталогов и статически объявленных списков.
- Экспорт `window.__gptModelPicker` содержит `historicalModels` и `experimentalApiModels` для проверки списка из консоли.
- Диагностика запроса и backend-ответа выводит `Model`, `Thinking`, `Priority` и режим отдельными строками.
- Успешные строки перехвата `fetch`, загрузки каталогов и выбранных параметров не отображаются в статусе; перехват и каталоги появляются только при ошибках.

Локальная проверка:

`node --check GPT_MODEL_PICKER_v1.0.11.js`

## 1.0.10 — 2026-09-22

Уточнены сворачивание панели и название невмешивающегося режима выбора модели.

- При сворачивании меняется только высота панели; ширина остаётся равной ширине развёрнутого окна.
- После разворачивания пользовательская ширина и сохранённая высота снова используются без отдельной ширины для title bar.
- Псевдопункт выбора модели `Auto — не менять slug` переименован в `Не изменять модель`.
- Статусы выбора и исходящего запроса используют название `Не изменять модель`, чтобы оно не путалось с моделью Auto-auto из каталога.
- Внутреннее служебное значение этого пункта остаётся `auto`; логика невмешательства не менялась.
- Thinking effort `Auto` не переименован, поскольку это отдельный параметр рассуждения.

Локальная проверка:

`node --check GPT_MODEL_PICKER_v1.0.10.js`

Проверено, что Chat Mode ON/OFF и невмешивающийся режим модели сохраняют поведение 1.0.9, а CSS свёрнутой панели не задаёт отдельную ширину.

## 1.0.9 — 2026-09-22

Возвращён переключатель `Chat Mode` как явное управление защитой Chat → Work.

- `Chat Mode ON` + ручной model slug применяет проверенное поведение ранних версий: `primary_assistant`, `conversation_origin=null`, без Work execution target и `tpp_work_handoff_conversion`.
- `Chat Mode OFF` применяет выбранный model slug, но оставляет параметры режима разговора штатными.
- `Auto` остаётся невмешивающимся режимом и не принуждает Chat даже при включённом `Chat Mode`.
- Состояние `Chat Mode` сохраняется в `gpt-model-picker.force-chat.v1`; при отсутствии сохранённого значения режим включён.
- Экспериментальная конвертация существующего Work обратно в Chat не возвращалась.

Интерфейс переработан в компактное изменяемое окно:

- добавлена отдельная title bar в визуальном подходе DropMe;
- слева отображается иконка;
- название `GPT Model Picker` и `ChatGPT · v1.0.9` разделены на две строки;
- шапка используется для перемещения окна и больше не выглядит как большая кнопка;
- уменьшены шрифты, поля и интервалы;
- `Скорость 1.5x` и `Chat Mode` размещены рядом;
- ширина и высота меняются стандартным resize-маркером;
- размер сохраняется в `gpt-model-picker.size.v1`;
- диагностический текст намеренно обрезается при маленьком размере и полностью виден после увеличения окна;
- свёрнутая title bar не перезаписывает сохранённый размер развёрнутого окна.

Локальная проверка:

`node --check GPT_MODEL_PICKER_v1.0.9.js`

Unit-тест подтвердил:

- `Chat Mode ON` удерживает ручную Work-модель в Chat-параметрах;
- `Chat Mode OFF` сохраняет штатные Work-параметры;
- `Auto` не меняет model slug и режим.

Браузерный тест выполняется после подключения 1.0.9 пользователем.

## 1.0.8 — 2026-09-22

Промежуточная упрощённая версия.

Основной сценарий упрощён до выбора модели и автоматического сохранения обычного Chat.

- Любой вручную выбранный model slug автоматически включает Chat-параметры для `primary_assistant`.
- `conversation_origin=null` передаётся явно.
- `conversation_mode` сохраняется как `{ kind: "primary_assistant" }`.
- Work execution target удаляется из верхнего уровня payload и metadata нового user-сообщения.
- `tpp_work_handoff_conversion` не передаётся.
- `Auto` не меняет model slug, origin, mode и execution target.
- Удалён переключатель `Оставаться в Chat`: для выбранного slug это теперь автоматическое поведение.
- Удалены кнопки `Применить сейчас`, `Обновить каталоги`, `Вернуть перехват` и `Work → Chat`.
- Выбор модели, ручной slug, thinking effort и скорость применяются сразу.
- Каталоги загружаются автоматически.
- Защита `window.fetch` восстанавливается автоматически.
- Удалён экспериментальный код восстановления и преобразования Work-разговоров.
- Панель и экспортируемый API содержат только используемые функции.
- Документация методов отражает фактическое автоматическое поведение.

Локальная проверка:

`node --check GPT_MODEL_PICKER_v1.0.8.js`

Unit-тест подтвердил:

- Work model slug применяется;
- `conversation_origin=null`;
- `primary_assistant` сохраняется;
- Work execution target удаляется;
- `tpp_work_handoff_conversion` удаляется;
- `service_tier=priority` применяется;
- `Auto` оставляет model slug и режим без изменений.

Браузерное тестирование 1.0.8 должно выполняться после подключения версии пользователем.

## 1.0.7 — 2026-09-22

Версия подтвердила основной сценарий.

### Work-модель в обычном Chat

Создан новый Chat с выбранной Work-моделью:

`gpt-5.6-sol-wm`

Исходящий запрос был преобразован из Work-параметров в Chat и получил HTTP 200.

После первого ответа server-side список разговоров вернул:

`conversation_origin = null`

Второй ход с той же Work-моделью также получил HTTP 200, после чего:

`conversation_origin = null`

сохранился.

Основная задача подтверждена: Work model slug работает в обычном Chat без создания Work-разговора.

Тестовый разговор удалён после проверки.

### Существующий прямой Work

На существующем Work с `conversation_origin="tpp"` следующий ход был отправлен с явным:

`conversation_origin=null`

Backend ответил HTTP 200, но после хода server-side origin остался:

`tpp`

### Ветка прямого Work

Создана новая штатная ветка Work-разговора.

Первый ход ветки отправлялся с явным `conversation_origin=null`, но после материализации ветки server-side origin также оказался:

`tpp`

Экспериментальная ветка удалена после проверки.

Также удалены экспериментальные ветки предыдущих тестов.

## 1.0.6 — 2026-09-22

Диагностическая версия.

На тестовой вкладке подтверждено:

- запущена `Модель ChatGPT v1.0.6`;

- после PATCH backend продолжает возвращать `conversation_origin="tpp"`.

Также проверен штатный маршрут ветвления:

`/branch/{conversation_id}/{message_id}`

Ветка успешно создаётся и принимает сообщения, но материализованный разговор также получает:

`conversation_origin="tpp"`
